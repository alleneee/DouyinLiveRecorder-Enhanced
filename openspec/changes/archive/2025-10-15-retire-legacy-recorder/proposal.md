# 提案：移除 Legacy Recorder 桥接层

## 摘要
- 使用 `app/core/recording` 中的现代工作器流水线替换运行时对 `LegacyRecorder` 的依赖。
- 将 legacy 适配层从在线录制流程中剔除，使 `RecordingApplication` 仅创建原生工作器。
- 更新规范，强制使用原生工作器并消除历史回退路径。

## 动机
- 目前运行时会启动 `LegacyRecorder`，导致逻辑重复、阻碍异步优化，并掩盖通过适配层抛出的错误。
- 移除 legacy 桥接后职责更清晰，测试更简单，也为后续优化（如原生 OSS 钩子、更完善的追踪）铺路。
- `RecordingArchitecture` 规范应体现演进后的系统，避免回退到 legacy 实现。

## 范围
### 范围内
- 运行时启动流程与工作器工厂的接线改造。
- 录制监督器到工作器的生命周期管理。
- 描述原生工作器使用方式的规范更新。
- 仍引用 legacy 模块的支撑服务所需的配套改造。

### 范围外
- 重写各平台抓流逻辑（短期内仍可复用 legacy spider/stream）。
- 与工作器桥接无关的后处理或 OSS 上传大调整。
- 运行时生命周期之外的 UI / API 协议变化。

## 验证
- 编写单元/集成测试，覆盖在无 `LegacyRecorder` 情况下监督器启停与房间状态传播。
- 通过手工脚本验证 OSS、分段录制场景仍可运行，直至自动化覆盖补齐。
- 规范变更需通过 `openspec validate` 校验。
