# 录制模式选择指南

## 📋 概述

系统支持两种录制模式，可以通过 API 参数灵活选择：

1. **分段录制模式**：每 20 分钟自动保存一个文件，上传到 OSS
2. **连续录制模式**：录制到直播结束，然后触发后处理流程

## 🎯 两种模式对比

| 特性 | 分段录制模式 | 连续录制模式 |
|------|------------|------------|
| 文件切分 | ✅ 每 20 分钟一个文件 | ❌ 一个完整文件 |
| OSS 上传 | ✅ 每段自动上传 | ❌ 不自动上传 |
| 数据库记录 | ✅ 每段都有记录 | ❌ 无数据库记录 |
| 后处理 | ❌ 不触发 | ✅ 直播结束后触发 |
| 适用场景 | 长时间直播、需要分段管理 | 短时间直播、需要完整文件 |
| 文件管理 | 多个小文件 | 一个大文件 |

## 🔧 使用方式

### 模式 1：分段录制（默认）

**特点**：
- 每 20 分钟自动保存一个文件
- 自动上传到 OSS
- 写入数据库记录
- 适合长时间直播

**API 调用**：
```bash
curl -X POST "http://localhost:8009/api/api/v2/recording/start" \
  -H "Content-Type: application/json" \
  -d '{
    "url": "https://live.douyin.com/296728101980",
    "nickname": "央视网财经",
    "quality": "OD",
    "enable_segment_recording": true
  }'
```

**工作流程**：
```
监控直播 → 检测开播 → 录制20分钟 → 保存文件1 → 上传OSS → 写入数据库
                    ↓
                录制20分钟 → 保存文件2 → 上传OSS → 写入数据库
                    ↓
                录制20分钟 → 保存文件3 → 上传OSS → 写入数据库
                    ↓
                直播结束
```

**文件命名**：
```
296728101980_央视网财经_标题_seg001_2025-01-15_11-33-51.ts
296728101980_央视网财经_标题_seg002_2025-01-15_11-53-51.ts
296728101980_央视网财经_标题_seg003_2025-01-15_12-13-51.ts
```

### 模式 2：连续录制

**特点**：
- 录制到直播结束
- 生成一个完整文件
- 直播结束后触发后处理流程
- 适合需要完整文件的场景

**API 调用**：
```bash
curl -X POST "http://localhost:8009/api/api/v2/recording/start" \
  -H "Content-Type: application/json" \
  -d '{
    "url": "https://live.douyin.com/296728101980",
    "nickname": "央视网财经",
    "quality": "OD",
    "enable_segment_recording": false
  }'
```

**工作流程**：
```
监控直播 → 检测开播 → 持续录制 → 直播结束 → 保存文件 → 触发后处理
                                              ↓
                                        后处理流程：
                                        1. 转换为 MP4（可选）
                                        2. 提取音频（可选）
                                        3. 生成 M3U8（可选）
                                        4. 上传到 OSS（可选）
                                        5. 发送通知（可选）
                                        6. 清理临时文件
```

**文件命名**：
```
296728101980_央视网财经_标题_2025-01-15_11-33-51.ts
```

## 📊 后处理流程详解

### 后处理管道（仅连续录制模式）

后处理流程由 `app/legacy/post_process/pipeline.py` 管理：

#### 1. 媒体处理
- **MP4 转换**：将 TS 文件转换为 MP4
- **音频提取**：提取音频为 MP3/M4A
- **M3U8 生成**：生成 HLS 切片

#### 2. OSS 上传
- 上传处理后的文件到 OSS
- 支持并发上传
- 自动重试机制

#### 3. 通知推送
- 钉钉通知
- 微信通知
- Telegram 通知
- 邮件通知

#### 4. 文件清理
- 删除原始文件（可选）
- 清理临时文件

### 配置后处理

在 `config/config.ini` 中配置：

```ini
[后处理设置]
是否生成m3u8 = 是
是否提取音频 = 是
是否上传oss = 是
上传成功后删除本地文件 = 是

[录制设置]
录制完成后自动转为mp4格式 = 是
mp4格式重新编码为h264 = 否
追加格式后删除原文件 = 是
```

## 🎨 使用场景建议

### 场景 1：长时间直播（推荐分段录制）

**示例**：24小时直播、马拉松直播

**优势**：
- 文件大小可控
- 失败影响小（只影响当前分段）
- 便于管理和检索
- 自动上传到 OSS

**配置**：
```json
{
  "enable_segment_recording": true
}
```

### 场景 2：短时间直播（推荐连续录制）

**示例**：1-2小时的直播、活动直播

**优势**：
- 完整的单个文件
- 便于后期处理
- 可以转换格式
- 可以提取音频

**配置**：
```json
{
  "enable_segment_recording": false,
  "converts_to_mp4": true
}
```

### 场景 3：需要完整文件 + 分段管理

**方案**：使用连续录制 + 后处理切片

**配置**：
```json
{
  "enable_segment_recording": false
}
```

在 `config.ini` 中：
```ini
[后处理设置]
是否生成m3u8 = 是
m3u8切片时间(秒) = 1200  # 20分钟切片
```

## 🔍 API 参数说明

### StartRecordingRequest

| 参数 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| `url` | string | 必填 | 直播间 URL |
| `nickname` | string | 必填 | 主播昵称 |
| `quality` | string | "OD" | 画质代码 |
| `video_save_type` | string | "TS" | 保存格式 |
| `converts_to_mp4` | boolean | false | 是否转换为 MP4 |
| `folder_by_author` | boolean | true | 按作者分文件夹 |
| **`enable_segment_recording`** | **boolean** | **true** | **启用分段录制** |

### enable_segment_recording 详解

- **`true`**（默认）：分段录制模式
  - 每 20 分钟一个文件
  - 自动上传 OSS
  - 写入数据库
  - 不触发后处理

- **`false`**：连续录制模式
  - 录制到直播结束
  - 一个完整文件
  - 触发后处理流程
  - 不自动上传（由后处理决定）

## 💡 最佳实践

### 1. 根据直播时长选择

```python
# 预计直播时长
estimated_duration = 3600  # 秒

if estimated_duration > 7200:  # 超过 2 小时
    enable_segment_recording = True  # 使用分段录制
else:
    enable_segment_recording = False  # 使用连续录制
```

### 2. 根据存储策略选择

```python
# 如果需要 OSS 自动管理
enable_segment_recording = True

# 如果需要本地后处理
enable_segment_recording = False
```

### 3. 混合使用

对于重要直播：
1. 使用分段录制作为主录制（自动上传 OSS）
2. 同时启动连续录制作为备份（本地完整文件）

```bash
# 主录制：分段模式
curl -X POST ".../start" -d '{"url": "...", "enable_segment_recording": true}'

# 备份录制：连续模式（使用不同的 nickname 避免冲突）
curl -X POST ".../start" -d '{"url": "...", "nickname": "备份", "enable_segment_recording": false}'
```

## 📈 性能对比

### 磁盘占用

| 模式 | 磁盘占用 | 说明 |
|------|---------|------|
| 分段录制 | 低 | 上传后可删除本地文件 |
| 连续录制 | 高 | 需要保留完整文件直到后处理完成 |

### 网络带宽

| 模式 | 上传带宽 | 说明 |
|------|---------|------|
| 分段录制 | 平稳 | 每 20 分钟上传一次 |
| 连续录制 | 峰值 | 直播结束后集中上传 |

### 可靠性

| 模式 | 可靠性 | 说明 |
|------|--------|------|
| 分段录制 | 高 | 失败只影响当前分段 |
| 连续录制 | 中 | 失败影响整个录制 |

## 🐛 故障排查

### 问题 1：分段录制没有触发后处理

**原因**：分段录制模式不触发后处理

**解决**：如需后处理，请使用连续录制模式

### 问题 2：连续录制没有上传到 OSS

**原因**：连续录制模式由后处理决定是否上传

**解决**：在 `config.ini` 中配置：
```ini
[后处理设置]
是否上传oss = 是
```

### 问题 3：文件太大导致处理失败

**原因**：连续录制生成的文件过大

**解决**：
1. 使用分段录制模式
2. 或增加磁盘空间
3. 或缩短录制时长
