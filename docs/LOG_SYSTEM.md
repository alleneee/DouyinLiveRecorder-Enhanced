# 日志系统说明

## 日志配置 (FastAPI应用)

### 配置文件位置
- **主配置**: `app/logger.py` - FastAPI应用专用日志配置
- **旧配置**: `src/logger.py` - 控制台脚本使用(已废弃)

### 输出目标

1. **控制台输出 (stderr)**
   - 级别: INFO 及以上
   - 格式: 带颜色的时间戳 + 级别 + 消息
   - 用途: 实时监控运行状态
   - 适用: uvicorn运行时可见

2. **主日志文件 (logs/recorder.log)**
   - 级别: INFO 及以上
   - 格式: 时间戳 + 级别 + 消息
   - 轮转: 每 10MB 轮转一次
   - 保留: 7 天
   - 用途: 完整链路追踪和问题排查

3. **错误日志文件 (logs/error.log)**
   - 级别: ERROR 及以上
   - 格式: 时间戳 + 级别 + 消息 + 异常堆栈
   - 轮转: 每 5MB 轮转一次
   - 保留: 30 天
   - 用途: 快速排查错误和异常

### 统一日志的优势

✅ **完整链路追踪** - 所有日志在recorder.log中,按时间顺序排列
✅ **时序准确** - 避免多文件时间戳不同步问题
✅ **问题定位快** - 无需切换多个文件查看上下文
✅ **错误独立** - 错误日志单独保存,便于快速查看
✅ **日志量可控** - 通过轮转和保留策略管理磁盘空间

## 日志级别使用规范

### INFO - 关键流程节点
记录业务流程的关键节点,用于追踪完整链路:

```
✓ 监听启动/停止
✓ 检测到开播/下播
✓ 录制会话创建/结束
✓ FFmpeg启动/停止
✓ 分片处理完成
✓ OSS上传成功
```

### WARNING - 异常但可恢复
记录异常情况但系统可以继续运行:

```
⚠ 直播间不存在
⚠ 直播未开播
⚠ OSS分片上传重试
⚠ 监听线程已存在
```

### ERROR - 错误需要关注
记录错误和异常,需要人工介入:

```
✗ OSS上传失败
✗ 录制异常
✗ FFmpeg异常终止
✗ 分片处理失败
```

## 日志上下文格式

统一使用 `[平台 | 房间ID | 会话ID | 分片ID]` 格式:

```
[抖音 | 296728101980 | c840ef38] 监听线程启动
[抖音 | 296728101980 | c840ef38] 检测到开播
[抖音 | 296728101980 | c840ef38] 启动FFmpeg录制
[抖音 | 296728101980 | c840ef38 | seg1] OSS上传成功, type=multipart, size=100MB
[抖音 | 296728101980 | c840ef38 | seg1] 分片处理完成
[抖音 | 296728101980 | c840ef38] FFmpeg录制完成
[抖音 | 296728101980 | c840ef38] 检测到下播
```

### 上下文层级

- **最小上下文**: `[平台 | 房间ID]` - 监听阶段
- **录制上下文**: `[平台 | 房间ID | 会话ID前8位]` - 录制阶段
- **分片上下文**: `[平台 | 房间ID | 会话ID前8位 | seg编号]` - 分片处理

## 简化原则

### 移除的冗余日志

❌ 上传进度日志 (每个分片10%, 20%, ...)
❌ 文件操作细节 (删除成功、创建目录)
❌ 中间步骤提示 ([1/4]、[2/4]、...)
❌ 成功状态重复 (上传完成 + 回写成功)

### 保留的核心日志

✅ 启动/停止节点
✅ 状态变更事件 (开播/下播)
✅ 最终处理结果 (成功/失败)
✅ 错误和异常信息

## 日志查看示例

### 查看今天的所有日志
```bash
tail -f logs/recorder.log
```

### 查看某个房间的录制日志
```bash
grep "296728101980" logs/recorder.log
```

### 查看某个会话的完整链路
```bash
grep "c840ef38" logs/recorder.log
```

### 只查看错误日志
```bash
grep "ERROR" logs/recorder.log
```

### 查看最近的告警
```bash
grep -E "WARNING|ERROR" logs/recorder.log | tail -20
```

## 维护建议

1. **定期清理** - 日志会自动轮转,但建议每月检查一次磁盘空间
2. **监控告警** - 可以设置定时任务监控ERROR日志,及时发现问题
3. **备份重要日志** - 对于重要的录制任务,可以单独备份相关日志
4. **调整级别** - 如需排查问题,可临时将日志级别调整为DEBUG

## 日志文件位置

```
项目根目录/
└── logs/
    ├── recorder.log          # 主日志文件(所有级别)
    │   ├── recorder.log.2025-01-20_00-00-00  # 轮转后的历史日志
    │   └── ...
    └── error.log             # 错误日志文件(仅ERROR)
        ├── error.log.2025-01-20_00-00-00     # 轮转后的错误日志
        └── ...
```

## 使用方法

### 在代码中使用日志

```python
from app.logger import logger

# INFO级别 - 关键流程节点
logger.info(f"[抖音 | 296728101980] 监听线程启动")

# WARNING级别 - 异常但可恢复
logger.warning(f"[抖音 | 296728101980] 直播未开播")

# ERROR级别 - 错误需要关注
logger.error(f"[抖音 | 296728101980] OSS上传失败: {e}", exc_info=True)
```

### 启动FastAPI应用

```bash
# 方式1: 直接运行(日志输出到控制台+文件)
uvicorn app.main:app --host 0.0.0.0 --port 8000

# 方式2: 使用启动脚本
./start_api.sh
```
